A practical walkthrough of every part of the admin — what it's for, and the order that usually makes sense to use things in.
🚀 First things to set up

1. Branding

Admin → CMS → Branding. Set your site name, logo, favicon, and the default player banner (the fallback image used behind the music player when a track has no banner, artist photo, or album cover of its own).

2. SEO

Admin → CMS → SEO. Set your site's default meta title/description, Open Graph image, and Twitter card — these apply everywhere unless a specific page overrides them. Also where you paste Google/Bing site-verification codes and edit robots.txt. Your sitemap is always live at /sitemap.xml, and robots.txt at /robots.txt — both update automatically as you publish content.

3. AI Settings

Admin → AI Settings. Add API keys for any provider — Anthropic (Claude), Google Gemini, OpenRouter (one key, 100+ models), OpenAI, or Stability. Used for AI image generation, blog writing, content moderation, and (as a last-resort fallback only) AI movie/episode scene summaries. Use the Test Connection button next to each provider to confirm the key actually works — it makes a real cheap call and shows the exact error if something's wrong, instead of you finding out later when a feature silently fails.

🌐 A note on hosting limits (PythonAnywhere free tier)

If this site runs on PythonAnywhere's free plan, outbound requests are restricted to a fixed allowlist of domains — this isn't a bug in the site, it's a platform-level restriction that applies no matter what API key is saved. A blocked domain shows up as something like URLError: Tunnel connection failed: 403 Forbidden.

What's whitelisted (works fine on free tier): TMDB, Archive.org, iTunes, Pexels, Pixabay, YouTube Data API, AudD, OpenSubtitles, LRCLIB.

What's NOT whitelisted (needs a paid PythonAnywhere plan): Jamendo. If you need full-length music imports specifically, the cheapest fix is upgrading to PythonAnywhere's "Hacker" plan (~$5/month), which removes the domain restriction entirely — not just for Jamendo, for everything.

Use Admin → System → Network Diagnostics any time to test every integration at once and see exactly which domains are reachable.

🎵 Getting music onto the site

Option A — Upload it yourself

Admin → Music → Add Track. Upload the audio file (or paste a direct link), cover image, and optional banner image, then publish.

Option B — Fetch from iTunes

Admin → Fetch Music. Search, or browse Trending/Latest/By Genre. Select tracks (individually or several at once) and choose Import as Pending or Import & Approve. Cover art and, where available, synced lyrics are pulled in automatically. What you get is a 30-second preview clip and metadata — not the full song, since no free service legally provides that. Edit the track afterward to attach the real audio file/link once you have the rights to it.

Already-imported tracks missing lyrics? Select them in the Tracks table and use the 📝 Fetch Synced Lyrics bulk button to try again.

Option C — Fetch full-length tracks from Jamendo

Admin → Fetch Music → Jamendo tab. Different from iTunes: these are real independent artists releasing full Creative-Commons-licensed songs, so what you import is the actual complete track, not a preview. Needs a free client_id from devportal.jamendo.com. Synced lyrics are fetched automatically here too, same as iTunes imports. Note: Jamendo needs a paid PythonAnywhere plan if hosted there — see the hosting-limits note above.

What is AudD, and what does it do?

Admin → Fetch Music → Discover tab. AudD is a song-recognition service — the same idea as Shazam. It's not for importing your library; it's for the front-end "Discover" feature where a listener can record a few seconds of audio playing around them and the site tells them what song it is. Get a free key at audd.io, paste it in, and that feature starts working. It has nothing to do with iTunes or Jamendo imports.

Approving content

Individually: use the Live/Draft toggle on each row. In bulk: tick the checkboxes on the left of the Tracks/Movies table and use the action bar that appears (Approve / Set Draft / Delete).

Banners & missing cover art

Admin → Fetch Images. Search free stock photos (Pexels) or generate one with AI, then apply it as a specific track's banner, a movie's thumbnail, or the site-wide default. There's also a quick link straight to this from the Banner field inside Edit Track.

🎬 Getting movies onto the site

Fetch from TMDB

Admin → Fetch Movies. First visit asks for a free TMDB API key. Same Search/Trending/Now Playing/By Genre browsing as music. You get poster, synopsis, rating, genre, real cast (names, characters, photos), and an official trailer automatically — never the full movie (same licensing reality as music, and this covers Hollywood, Nollywood, Bollywood, and everything else TMDB catalogues equally). Edit the movie afterward and paste a real video link, or upload a file, into Video URL / Video File.

Pasting a YouTube link into either Video URL or Trailer URL works fine — it gets embedded properly regardless of which link format YouTube gave you.

Already-imported movies missing cast info? Select them in the Movies table and use the Fetch Cast bulk action.

Fetch real, full, watchable movies from Archive.org

Admin → Fetch Movies → Archive.org tab. No key needed. These are real public-domain films — legally free to stream in full, resolved to an actual playable video automatically on import (no manual video link needed, unlike TMDB imports). The honest limit: public domain means these are inherently older films (pre-1929 in the US, or specific titles explicitly released into the public domain) — there is no legal free source for recent Hollywood, Nollywood, or Bollywood full movies, because those are still commercially licensed content. Anything claiming to offer that for free isn't operating legally, and isn't something this site integrates with.

Real subtitles — not AI-dependent

The Subtitles button on any movie/episode page now tries, in order: (1) a subtitle already saved on that item, (2) a real .srt file fetched live from OpenSubtitles — the same database VLC uses, synced to the actual scene — and (3) only if neither of those found anything, an AI-generated scene summary as a last resort (clearly labelled as such, and only runs if an AI provider is configured). Set up OpenSubtitles once in Admin → Fetch Movies and it applies everywhere automatically going forward.

Player: width and seek gestures

The movie player has a Fit / Full Width toggle in its header (remembered per-device), and double-tapping the left or right third of the video seeks ±10 seconds — same gesture as YouTube/Netflix's mobile apps. Native player controls (play/pause, scrubber, volume) stay fully usable underneath.

🎞 Shorts — real audio via YouTube

Why Pexels/Pixabay shorts are silent

That's not a bug — those are stock b-roll libraries, and most of that footage genuinely has no audio track by design. For short-form content with real sound (comedy, skits, etc.), use the YouTube provider instead — it plays through YouTube's own official embedded player, so it carries real audio.

Getting a YouTube API key, step by step

  1. Go to console.cloud.google.com and sign in with any Google account.
  2. Top-left, click the project dropdown → New Project. Give it any name (e.g. "NEXUS Shorts") → Create.
  3. Make sure that new project is selected in the dropdown (it can take a few seconds to appear after creating it).
  4. In the search bar at the top, type "YouTube Data API v3" and open it from the results.
  5. Click the blue Enable button.
  6. In the left sidebar, go to Credentials → + Create Credentials → API key.
  7. A key appears immediately — copy it and paste it into Admin → Fetch Shorts → YouTube panel here.

That's the whole thing — no billing setup or approval wait required for basic search usage. Free tier gives 10,000 "quota units" per day, and each shorts search here uses about 100 units, so that's roughly 100 searches/day before it resets.

🖋 Blog, Images & other content

Admin → Blog and Admin → Images manage those libraries the same way — upload directly, or approve/reject what creators submit through Creator Studio.

Admin → Content is the unified moderation queue for everything creators upload through Creator Studio (music, video, images, blog), separate from your own direct uploads above.

👥 Creators & payouts

Creators upload their own content through Creator Studio (front-end, not in this admin) — it lands in the Content moderation queue here for you to approve. Their earnings accumulate in an in-app Wallet, and withdrawal requests show up under Admin → Monetization for you to process.

🛠 Site management

Pages

Admin → CMS → Pages. About, Privacy, Terms, Refund Policy, FAQ, Contact, Community Guidelines, and Cookie Policy already have real content — edit any of them here any time.

Theme

Admin → CMS → Theme. Adjust site-wide color variables. Changes here layer on top of the built-in look, so you can nudge things without starting from scratch.

System & Automation

Admin → System shows health/cache status. Admin → Automation manages scheduled jobs and workflows, if you're using them.

Maintenance mode

Found in Settings — flip this on when doing major work, with an option to still let admins and specific IPs through.

✅ A sensible weekly routine
  1. Check Content for anything creators submitted, approve or reject.
  2. Check the Tracks/Movies tables for anything still Pending from Fetch and approve in bulk.
  3. Skim Monetization for pending withdrawal requests.
  4. Once a month or so, glance at SEO and Branding to make sure nothing needs updating.
